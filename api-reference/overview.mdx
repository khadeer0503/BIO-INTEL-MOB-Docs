# WordPress API reference

The API reference uses `openapi/wordpress.yaml` and currently covers the user-provided Rome dataset endpoint. Inspect the WordPress plugin routes and payloads before expanding the contract.

## Pilot sites

Each city has a separate WordPress deployment. Verify that a host exposes the same route and schema before adding a `servers` entry. Use a separate OpenAPI file or a clearly versioned contract when a site differs materially.

## API playground

The Mintlify playground uses interactive mode (`"mode": "interactive"` in `docs.json`), which enables the "Send Request" / "Try It" button in the browser.

### CORS & connectivity verification

For browser requests from `https://ct-lup.mintlify.site` (or `http://localhost:3000` locally):

- DNS & Server: Host `rome.bio-intel-mob.eu` resolves to IP `82.165.59.103` (nginx/1.30.4 + PHP 8.3).

- Endpoint: `https://rome.bio-intel-mob.eu/wp-json/api/datasets`

- CORS Support: The WordPress server responds dynamically with:
  ```http
  Access-Control-Allow-Origin: <Request-Origin>
  Access-Control-Allow-Methods: OPTIONS, GET, POST, PUT, PATCH, DELETE
  Access-Control-Allow-Credentials: true
  Vary: Origin
  ```

- Preflight (OPTIONS): Successfully handled with HTTP 200 OK.

- Payload Shape: Returns a JSON object with `id`, `city`, `generatedAt`, and an array of `proposals` (including geolocation coordinates, category, severity, status, images, and description).

> [!NOTE]
> For custom domains or local staging instances, check that the server accepts your origin or that `Access-Control-Allow-Origin` permits your hostname. If a browser request fails, check the DevTools Network tab for mixed content (HTTP vs HTTPS) and browser extensions that block cross-origin requests.

## Contract workflow

1. Inspect the route registration in the WordPress plugin.
2. Capture a sanitized, representative response from staging.
3. Add explicit schemas, parameters, errors and authorization details to OpenAPI (`openapi/wordpress.yaml`).
4. Validate with `mint openapi-check openapi/wordpress.yaml`.
5. Review and merge the documentation change.
